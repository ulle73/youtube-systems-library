# Implementation

## Current status
No runtime installation, paid generation, account connection or commercial test was performed for this reconstruction.

## Minimum safe implementation

### Phase 1 — Brief
Create one structured persona/brand file with:
- audience;
- purpose;
- disclosed synthetic status;
- visual identity;
- tone/voice;
- allowed/disallowed content;
- owned/licensed reference assets;
- CTA and destination;
- measurement fields.

### Phase 2 — Creative batch
Generate a small batch, not hundreds of assets. Store:
- generation prompt/brief;
- model/tool/version;
- input asset rights/provenance;
- output IDs;
- reject reasons;
- accepted asset.

### Phase 3 — Short-form experiment
Produce a limited number of comparable pieces using the source's hook/buildup/trigger/reaction/CTA grammar. Tag each asset with an archetype/test ID.

### Phase 4 — Attribution
Use standard campaign/channel tracking and a transparent destination. Preserve the creative/test ID if possible through conversion analytics.

### Phase 5 — Bounded automation
Automate only greeting, routing, FAQ/context capture or other approved low-risk tasks. Keep a visible escalation path. Never hide that automation/synthetic content is AI where disclosure is required.

### Phase 6 — Evaluation
Compare:
- cost per accepted asset;
- active human minutes;
- publish/reject rate;
- landing behavior;
- conversion;
- repeat/retention if relevant;
- correction/escalation rate.

## Adoption rule
Do not expand because generation is cheap or visually impressive. Expand only when repeated measured cases improve the target business outcome enough to justify production, review and maintenance.

## Explicit exclusions
This implementation does not include:
- account/device fingerprint manipulation;
- static/rotating proxy tactics intended to influence platform detection;
- guardrail bypass;
- unauthorized real-person likeness use;
- deceptive "AI pretending to be human" behavior.
