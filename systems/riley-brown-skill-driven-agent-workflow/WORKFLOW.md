# Workflow

## Phase 1 — Prove the work before encoding it

1. Start with a real task the operator actually needs completed.
2. Use the agent interactively to solve it.
3. Judge the output against a concrete outcome standard.
4. Iterate until the procedure produces a useful result.
5. Watch for repetition: if the same useful process is needed again, it becomes a skill candidate.

## Phase 2 — Promote repeated procedure to a skill

6. Ask the agent to capture the successful repeatable procedure as a reusable skill.
7. Keep current task material/context separate from the durable method wherever possible.
8. Give the skill a clear expected output so later runs can be judged consistently.

## Phase 3 — Outcome-driven QA

9. Start a representative task using the saved skill.
10. Judge the actual result, not merely whether the skill file looks elegant.
11. If the outcome is weak, tell the agent precisely what failed or what good should have looked like.
12. Update the skill from that feedback.
13. Start a fresh conversation/context.
14. Run the skill again on a representative case.
15. Repeat until performance is acceptably stable for the task's risk level.

## Phase 4 — Compose proven primitives

16. Search the existing skill library before creating another monolithic workflow.
17. Combine relevant mature skills when a new task can be expressed as a chain of existing capabilities.
18. Test the composition as a new workflow; do not assume reliable parts automatically create a reliable whole.
19. Promote a recurring composition into its own orchestrated workflow only when the combination itself proves useful repeatedly.

**Source state:** Combination/mix-and-match is EXACT at 31:15–31:55. The promotion/QA rules for composites are RECONSTRUCTED.

## Phase 5 — Apply risk gate

20. Classify the consequence and reversibility of a bad run.
21. Low-risk creative/research work may use outcome-focused iteration with human quality judgment.
22. Higher-risk work requires explicit inspection of instructions, tools, data access, permissions and approval boundaries.
23. Mission-critical, payment, sensitive-document or destructive workflows require independent review/approval before external action.

**Source state:** Risk-dependent inspection is EXACT at 33:23–33:45. The detailed Golfkuponger governance categories are RECONSTRUCTED from this source plus existing Marketing Engineering research.

## Phase 6 — Choose execution environment

24. Keep interactive/local execution when the task benefits from local files, repository access or hands-on iteration.
25. Prefer cloud/unattended execution when a recurring task must run reliably without a user's computer remaining awake.
26. Do not confuse a stable skill with authorization to automate it; automation is a separate deployment and permission decision.
